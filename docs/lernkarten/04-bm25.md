# 04 BM25

**In einem Satz:** BM25 bewertet ein Dokument nach seinen Anfragewörtern: seltene Wörter zählen mehr (IDF), Wiederholungen sättigen (k1) und lange Dokumente werden gebremst (b).

## Kernidee

- **Termhäufigkeit** f(q, D): Wie oft steht q in D? Mehr ist besser, aber gesättigt: der TF-Teil geht nie über `k1 + 1`.
- **IDF** (Inverse Document Frequency): Wörter in wenigen Dokumenten bekommen großes Gewicht, Allerweltswörter kleines.
- **IDF-Variante mit +1 (ADR 0003, Lucene):** immer > 0. Die klassische Robertson-Formel wird negativ, sobald df > N/2, und bestraft dann Treffer.
- **Längennormierung:** `L = |D| / avgdl`; kürzer als der Schnitt → Treffer zählen mehr. `b = 0` schaltet die Länge ab, `b = 1` normiert voll.
- **top_m:** nur Dokumente mit mindestens einem Anfragewort bewerten, die m besten per Heap, Score > 0.

## Formel / Ablauf

```
IDF(q)   = ln( (N − n(q) + 0.5) / (n(q) + 0.5) + 1 )
L        = |D| / avgdl
K        = k1 · (1 − b + b · L)
TF(q,D)  = f(q,D) · (k1 + 1) / (f(q,D) + K)          (0, wenn f = 0)
score(D) = Summe über die Anfragewörter q von IDF(q) · TF(q,D)
```

## Mini-Beispiel

Korpus aus Karte 03 (N = 3, avgdl = 3,33), Anfrage „apfel milch“, k1 = 1,5, b = 0,75:

| Schritt | Rechnung | Ergebnis |
|---|---|---|
| IDF(apfel) = IDF(milch) | ln((3 − 2 + 0,5) / 2,5 + 1) = ln(1,6) | 0,470 |
| Dok 0, \|D\| = 3 | L = 0,9; K = 1,3875; TF(apfel, f = 2) = 5 / 3,3875 = 1,476 | **0,694** |
| Dok 1, \|D\| = 2 | L = 0,6; K = 1,05; TF(milch) = 2,5 / 2,05 = 1,220 | **0,573** |
| Dok 3, \|D\| = 5 | L = 1,5; K = 2,0625; TF je Wort = 0,816; 2 · 0,470 · 0,816 | **0,767** |

`top_m("apfel milch", m = 2)` → `[(3, 0.767), (0, 0.694)]` (Test `test_top_m_reference_m2`). IDF-Vergleich bei N = 3, df = 2: klassisch −0,511, mit +1 0,470 (ADR 0003).

## Komplexität

IDF O(\|q\|), Kandidaten O(P), Bewerten O(C · \|q\|), Top-m per Heap O(C · log m) statt O(C · log C). Gesamt O(P + C · \|q\| + C · log m).

## Typische Prüferfragen

- **Warum +1 in der IDF?** Bei kleinen Korpora steht das Suchwort oft in mehr als der Hälfte der Chunks; ohne +1 würde es negativ gewichtet.
- **Was bewirken k1 und b?** k1 steuert die Sättigung (k1 = 0: nur „kommt vor“), b die Längenbremse (b = 0: Länge egal).
- **Warum hat das Hauptschlagwort eine IDF nahe null?** arXiv liefert die Dokumente gerade wegen des Schlagworts; es steht in fast jedem Chunk (`uml` 0,10). Richtige Formel, falscher Korpus (L2).
- **Warum Heap statt Sortieren?** Nur die m besten werden gebraucht: O(C · log m).

## Stolperfallen

- Bei k1 = 0 und f = 0 wäre `f + K = 0`: deshalb gibt `compute_term_score` bei f = 0 sofort 0 zurück (Abweichung 6.2).
- Auf Abstracts filtert top_m kaum (22–29 Chunks < m = 50, ≈ 10 % aussortiert); BM25 ist dort vor allem Ranking-Signal (L1).
