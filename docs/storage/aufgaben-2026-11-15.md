## 1. Bug in `insert_chunks.sql` (ca. 20–30 min)

**Symptom:** Aus Python heraus scheitert die Datei mit

```
function unnest(unknown) is not unique
```

In DataGrip passiert das nicht. Der Unterschied: psycopg schickt eine Python-Liste von Strings **ohne Datentyp** an Postgres. Für `unnest` gibt es mehrere Varianten, und ohne Typ kann Postgres nicht entscheiden, welche gemeint ist.

**Leitfragen**
1. Warum läuft `insert_search.sql` mit `unnest(%(document_ids)s)`, obwohl es dasselbe Muster ist? (Tipp: Welchen Typ haben die Elemente dort?)
2. Wie sagst du Postgres in SQL ausdrücklich, welchen Typ ein Wert hat? Stichwort: Typumwandlung (Cast).
3. Welcher Array-Typ passt zur Spalte `chunks.text`?
